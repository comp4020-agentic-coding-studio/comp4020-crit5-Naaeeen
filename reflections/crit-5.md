# Crit 5 reflection

## What was the breakthrough that moved the work forward?

The breakthrough was separating what could be proven mechanically from what
had to be experienced. Once collision, timing, edge spawning and difficulty
became pure functions with injected randomness, I could watch a test fail for a
specific reason and make it green without touching the interface. That freed
the browser session to answer different questions: could I understand the
opening without instructions, did being caught feel legible, and did the same
composition survive the phone viewport? The phone screenshot immediately found
a clipped title that all 33 automated checks had accepted. That was a useful
failure because it showed the harness working as a set of complementary
sensors, not one supposedly complete score.

## What did this work change about who I want to be as a software developer?

I want to be a developer who asks what evidence would genuinely change my
mind. An agent can produce a polished-looking loop quickly, but speed creates
cognitive debt when I accept code I have not run or interactions I have not
felt. This build made me prefer a small mechanic carried all the way through:
deterministic rules, an original visual language, real loss and replay, exact
viewport play, and a concise record of corrections. I also want repository
instructions to stay thin and current. A stable rule belongs in the harness, a
weekly design belongs in the plan, and a judgement about fun still belongs in
human hands.
